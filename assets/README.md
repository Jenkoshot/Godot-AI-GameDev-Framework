# Asset Repository

A shared, git-tracked library of game-agnostic raw assets — 3D models, textures, audio — pulled
out of past projects or generated by `../model-generation/`.

> **This library is currently empty.** The category folders exist as placeholders; nothing ships
> pre-filled.

## Structure

The top level splits by asset kind, matching where `HARVEST-REPO.md` writes:

```
assets/
├── models/       3D meshes (.glb / .gltf) and their textures
│   ├── building_pieces/     Modular walls, floors, roofs, architectural structures
│   ├── characters/          Player characters, NPCs, enemies
│   ├── environment_assets/  Trees, rocks, terrain meshes, foliage
│   └── props/               Interactive objects, clutter, furniture, items
├── music/        Background tracks and stingers
├── sfx/          Sound effects
└── vfx/          Visual effect resources (textures, gradients, curves)
```

The four subdirectories under `models/` are the categorisation an agent uses when deciding where a
new mesh belongs. Put a model directly in `models/` only if it genuinely fits none of them.

## Import settings matter

Dropping a raw file into a Godot project generates a `.import` file, and the defaults are usually
wrong: pixel art comes out blurry, and 3D models arrive without collision. Every agent handling
raw assets is required to read `markdowns4AI/ASSET-STANDARDS.md` in the consuming project and
configure the `.import` by hand — nearest-neighbour filtering and no compression for pixel art,
collider generation and correct scale for meshes.

## How agents find these

Through `../global-index/README.md`, which is generated from what is actually here:

```bash
python framework_tools/build_global_index.py
```

Run it after adding or removing anything. Give a model a companion `.md` of the same base name if
you want it to carry a description in the index.

## Where models come from

Two routes:

1. **Harvested** from a project via `HARVEST-REPO.md`.
2. **Generated** procedurally in `../model-generation/`, which writes a JavaScript recipe that
   constructs the mesh mathematically rather than hallucinating binary geometry. Build output
   lands in `model-generation/dist/` as `.glb`; copy the ones worth keeping here.
